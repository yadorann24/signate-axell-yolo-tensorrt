# モデル・変換設定とテスト

## 競技提出の公式結果

yadorann24として個人参加したAxell AI Contest 2025の最終リーダーボードは **35位・銅メダル**、AP@[.50:.95]は **0.9674124323323867**、公式掲載推論時間は **0.016470296秒 / 画像**（16.470296 ms）です。[公式最終結果](https://user.competition.signate.jp/ja/competition/detail/?competition=6e644a0277314ba2a1d36a1634f75f41&task=cc969d0e55a44990becf0c0688235765&tab=leaderboard&leaderboard=private)

以下にモデル・変換設定と依存環境をまとめます。条件をそろえて推論結果や時間を比較する手順は[推論・ベンチマーク](benchmark.md)を参照してください。

## 変換設定

exportの条件を9種類のpresetへ整理しています。入力サイズは**高さ × 幅**です。FP16 / INT8は要求する数値精度、workspaceはTensorRT構築時に指定する作業メモリです。

| preset | 入力サイズ | 数値精度 | NMSを組み込む | workspace (GiB) |
| --- | --- | --- | --- | ---: |
| `fp16-640-raw-w2` | 640 × 640 | FP16 | いいえ | 2 |
| `fp16-640-raw` | 640 × 640 | FP16 | いいえ | 4 |
| `fp16-640-nms` | 640 × 640 | FP16 | はい | 4 |
| `fp16-512x768-nms` | 512 × 768 | FP16 | はい | 4 |
| `int8-512x768-raw` | 512 × 768 | INT8 | いいえ | 6 |
| `fp16-704x1056-nms` | 704 × 1056 | FP16 | はい | 4 |
| `fp16-800-nms` | 800 × 800 | FP16 | はい | 4 |
| `fp16-864-nms` | 864 × 864 | FP16 | はい | 4 |
| `fp16-896-nms` | 896 × 896 | FP16 | はい | 4 |

共通設定は`format="engine"`、`batch=1`、`dynamic=False`、`simplify=True`です。INT8は`half=False`、`int8=True`、`fraction=0.30`を指定します。各引数は`axell-export describe-preset --preset 名前`で確認できます。

## 登録モデル

| 系列 | 選択できるモデル名 |
| --- | --- |
| YOLO11 | `yolo11n`、`yolo11s`、`yolo11m`、`yolo11l`、`yolo11x` |
| YOLO12 | `yolo12n`、`yolo12m`、`yolo12l` |

モデル名は未学習のネットワーク構成を選ぶために使います。変換では利用者が指定したcheckpointの構成・重みを使用し、presetで入力サイズや数値精度などを設定します。同じ名前とpresetでも、checkpointが異なれば推論結果は変わります。

## 依存環境

Python 3.11または3.12を使用します。主要な依存関係は`pyproject.toml`で次のバージョンへ固定しています。

| ライブラリ | バージョン | 用途 |
| --- | --- | --- |
| PyYAML | 6.0.2 | 基本設定・素材一覧の読込 |
| Ultralytics | 8.3.170 | YOLOのモデル・学習・推論・export |
| PyTorch / torchvision | 2.4.0 / 0.19.0 | モデルとテンソル処理 |
| NumPy / OpenCV | 1.26.4 / 4.11.0.86 | 画像・矩形・画素操作 |
| ONNX / onnxslim | 1.16.2 / 0.1.59 | export中のONNX変換と簡略化 |
| onnxruntime-gpu | 1.22.0 | GPU用export環境の依存関係 |
| tensorrt-cu12 | 10.13.0.35 | CUDA 12向けTensorRT変換 |

CPU依存関係は、Linux x86_64・CPython 3.12向けの`requirements-cpu.lock`へ固定しています。設定検査、モデル構成、Copy-Pasteと学習への接続、推論計測を確認するための環境です。GPU用の構築手順は[README](../README.md)を参照してください。実行時のライブラリ・GPU情報は`export.json`に記録します。

TensorRT engineの実行可否や性能はGPU・ドライバ・CUDAなどの環境に依存するため、変換・推論時の環境を実行記録へ保存します。

## テストで確認すること

LinuxのCPU環境で、合成画像とランダム初期化モデルを用いて検証します。[Copy-Paste](solution.md)では実際の学習データローダーと学習ループを動かし、正解ラベルの維持やepoch間の設定変更を確認します。

| 対象 | 確認する内容 |
| --- | --- |
| モデルとpreset | 名前、入力サイズ、数値精度、NMSなどの設定が一貫していること |
| モデル生成 | 8モデルを指定クラス数で生成し、合成入力を使ったforwardが実行できること |
| 負例素材 | 指定した素材クラスだけを切り出し、元画像・ラベルを変更せず、不正な一覧やアノテーションを拒否すること |
| Copy-Paste | 元の正解枠を覆わず、追加物体へラベルを付けず、元画像・正解ラベルを変更しないこと |
| 学習への接続 | 実際の2 workerから得るバッチへ貼り付けを反映し、Mosaic終了後も保持し、終盤の無効化時には古い先読みバッチを残さないこと |
| 学習ループ | 合成画像でCPUの学習を2 epoch実行し、重みの更新、有限値の損失、checkpoint保存、2 epoch目でのCopy-Paste無効化を確認すること |
| 検証データ | Copy-Pasteを適用しないこと |
| 入力検証 | 存在しないcheckpointや不正な設定を受け付けないこと |
| calibration | 固定seedでの抽出と先頭抽出の再現、採用画像の内容変更検出、512 × 768のRGB uint8への変換、原画像を変更しないこと |
| NMS設定 | confidence・IoU・検出数上限を保存・伝播し、固定版の実NMS wrapperで動作を確認すること |
| 推論計測 | CPUのランダム初期化YOLOと合成画像で、推論・出力保存を実行すること。代替backendでwarmupの除外・同期の呼出順序・件数を確認すること |
| 出力管理 | 既存の出力を上書きせず、変換処理の結果を取り違えないこと |
| exportの制御 | 変換処理を代替するテストで、引数と成功・失敗の扱いを確認すること |
| 公開ファイル | データ、重み、画像、秘密情報を公開対象へ含めないこと |

テストには競技の配布データを使用しません。学習ループのテストではフォント確認処理を置き換え、外部の学習済み重みのダウンロードを禁止した状態で、学習・検証・保存を実行します。
